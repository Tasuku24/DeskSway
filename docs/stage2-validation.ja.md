# DeskSway 第2段階・実装と検証記録

日付：2026-11-04。環境：macOS 27.2、Apple Silicon、Xcode 27.2、Swift 6.4.2。

## 2026-11-05 設定画面を開いたまま動作

ユーザーが設定を閉じた状態で正常に移動することを確認。停止原因は設定画面を開いている間の停止仕様だった。追加要望に従い、画面の表示状態を変換の停止条件から外した。「保存」は画面を開いたまま設定を反映し、未保存の変更は実行中の設定へ影響しない。明示的な入力記録中（記録終了処理と押したキーの解放待ちを含む）のみ変換を抑止する。スクロール監視自体は継続し、記録途中の入力からそのまま変換へ切り替わることを防ぐ。案内と実行ボタンの表示も更新。既存50テスト成功。Releaseビルド・署名検証も成功。更新版を再起動し、新しい案内と保存済みのキー・横入力・0秒設定の保持を実画面で確認した。ただし更新後は3権限が再び未認識となり、設定画面を開いたままの物理マウス動作は未確認。権限の再登録はユーザー操作が必要。

## 2026-11-05 キー送信の許可要求と保存ボタン

実画面でAccessibility／Input Monitoringが認識済み、キー送信だけ未認識という状態を確認した。実装ではキー送信の状態を`CGPreflightPostEventAccess`で調べていた一方、対応ボタンがAX用の許可要求しか呼んでいなかった。SDKの公開API定義に従い、専用の「キー送信を許可…」から`CGRequestPostEventAccess`を呼ぶ経路を追加した。許可要求は明示的なボタン操作時のみで、通常の状態再確認や起動時には行わない。許可チェックを緩めたり、TCCを書き換えたりする修正ではない。

「保存」と「保存して閉じる」を併設し、同じ検証・永続化処理を共有する。前者は画面を保持し、保存済みの基準値を更新する。Command-Sでも保存できる。設定画面を開いている間は変換停止を維持する。

全50テスト成功。新しいネイティブUIテストで、キー送信ボタンがAX用コールバックではなくキー送信用コールバックを呼ぶこと、および「保存」が永続化処理を呼び終了コールバックを発火しないことを確認。実際の設定画面でも「保存」を押し、既存のキー・横入力・0秒設定を維持したまま「保存しました」が表示され、画面が残ることを確認した。Release/ad-hoc署名検証も成功。

修正版の「キー送信を許可…」を操作後、ユーザーが「許可を認識済みに変わった」と報告した。キー送信権限の認識はユーザーによる実機確認済み。実際のSpace移動まで今回再検証したという意味ではない。更新後の署名不一致による再登録は別問題として残る。macOSの許可操作はユーザーが行い、エージェントから許可設定の変更や実キー送信は行っていない。

## 2026-11-05 待ち時間0秒の追加

追加要望により下限を0.00秒へ変更。0秒では有効な横イベントごとに移動を受け付ける。待ち時間以外の権限・状態検知・縦入力・慣性の保護条件は維持。0秒の保存／復元と、同一時刻の連続イベント・入力保護を回帰テストに追加した。初期値は0.60秒のまま。全48テスト、Releaseビルド、署名検証に成功し、実際の設定画面で0.00秒を選択できることも確認。確認後はユーザーが選択中だった0.10秒の未保存状態へ戻した。

## 2026-11-05 連続入力の待ち時間

ユーザーの追加要望により「一つのまとまり／ジェスチャーで1回まで」の制限を置き換えた。設定画面の「連続入力 → 次の入力までの待ち時間」で0.10〜2.00秒、0.05秒刻みに調整できる。既存設定のキー・方向・形式を維持し、新規項目の初期値は0.60秒。待ち時間経過後に新しい横イベントが届いた場合だけ次のショートカットを生成し、入力停止後のタイマー送信や追いつき送信はしない。慣性・縦優勢・権限不足・古い検知は引き続き変換しない。検知途切れ後は新しいまとまり／ジェスチャーが必要。

- 全46テスト成功。短い／長い間隔、境界値、同一操作中の繰り返し、待ち時間中に始まる次のジェスチャー、検知途切れ、CGEventの生成結果、旧形式の移行、保存・不正値を確認。
- Releaseビルドとad-hoc署名検証成功。独立レビューで追加の修正指摘なし。
- 実際の設定画面を確認し、スライダーを0.20秒へ変更して数値表示が追従し、「標準に戻す」で0.60秒に戻ることを確認。保存済みのキー（4修飾キー＋A/S）と横入力設定も引き継がれている。
- 更新前は3権限の認識を確認できたが、更新後は未認識へ戻った。既知のad-hoc再ビルドによる許可不一致があるため再登録が必要。今回も権限は変更していない。実マウスの連続移動は未確認であり、自動判定テストと区別する。

以降の「1回まで」などの記載は初期版の履歴。現行仕様はこの追記とREADMEを優先する。

## 設定統合の追記（同日）

初期版の下記記録に続き、ユーザーの要望で設定を統合した。キー選択式UIを直接記録へ変更し、横入力の方向・フェーズ形式も実入力から保存する。権限3項目の状態、再確認、システム設定への移動、アプリの場所、実行／一時停止を同じ画面へまとめた。旧ショートカット設定を移行し、左右のショートカットと横入力は一括保存する。

- 自動テストは37件成功。キーdown/upとリピート、キャンセル時の保持キー処理、左右反転が実際に生成キーへ反映されること、登録したフェーズ付き入力の1ジェスチャー1回制限、慣性通過、設定移行・破損を含む。
- 設定画面の表示・文字配置・既存設定の引継ぎをAXとスクリーンショットで確認。未認識の権限がある場合に記録を開始せず案内することも確認。初期版の画面未確認という制限は、この設定画面については解消した。VoiceOver・実マウス・キー記録の実入力成功はまだ未確認。
- システム設定の「Device Control and Data Access」ではDeskSwayがonだった。一方、実行中アプリのAX/listen/post判定は未許可。macOS TCCログに `Failed to match existing code requirement ... kTCCServiceAccessibility` があり、既存許可と再ビルドされたad-hoc署名の不一致を確認した。ログ本体や署名ハッシュは公開資料に含めない。
- したがって権限問題を「アプリ側の再確認で解決した」とは扱わない。今回のアプリをOS設定で再登録する必要があり、ユーザーの操作待ち。TCCの変更、権限の自動付与、他アプリの設定変更は行っていない。
- 独立レビューで「記録を中止した瞬間にキーを押したままだと、後続リピートが漏れる」を指摘された。再現テストRED→GREENで修正。入力待ち15秒を過ぎた後やフォーカス喪失後は新しいキーを記録せず、既に抑止したキーのreleaseまでだけ処理する。終了・再起動もそのキーを離すまでは実行しない。この動作を設定画面に明示した。
- 内部再起動で二つのGUIプロセスを重ねる方式は、この環境で画面が戻らなかったため採用しない。旧プロセス終了を待つ同じ実行ファイルの小さな補助モードから通常起動する方式へ変更。常駐ヘルパーやログイン項目は追加しない。修正版の「アプリを再起動」を実際に押し、新しい設定画面が表示され、既存の設定と未認識の権限状態が保持されることをAXで確認した。

以降は初期版の履歴。現在の使い方・入力範囲はREADMEを優先する。

## 現在の到達点

main上でローカル試用版を実装。独立アプリの実マウス受け入れは未完了。第1段階の状態検知結果を、そのまま完成アプリの動作保証へ拡張しない。

メニューバーの状態表示・実行／一時停止・ショートカット選択・権限案内・終了、設定保存、スクロール専用タップ、別キューでのAX読み取り、復帰時の検知破棄を実装。初回は一時停止。ショートカット初期値はControl＋左右矢印。今回の利用者の組み合わせは設定画面で4修飾キー＋A/Sへ合わせる必要がある。

## 自動検証

- `swift test`：23件成功。入力保護条件、500 msの鮮度境界、横／縦優勢、フェーズ・慣性の通過、ホイールのまとまりと600 ms間隔、設定の検証・保存を確認。
- 実CGEventオブジェクトで横のline/fixed/point/raw/accelerated各値を除去し、縦と第3軸、元イベントを維持することを確認。生成キーのコード、修飾キー、down/upを確認。テストはキーを送信しない。
- AX分類のエラー・競合、世代番号による古い走査結果の拒否、各要素へのタイムアウト適用、探索上限を検証。
- Releaseアプリをビルドし、Info.plistとad-hoc署名を検証。TeamIdentifierなし。署名・公証済み配布ではない。
- 共有AXリーダーを使うプローブを再コンパイル。未定義シンボルにCGEvent・CGS・SkyLightがないことを確認。今回のプローブ実行による画面状態の再検証はしていない。

独立レビューで見つかった次の2点は、再現テストが失敗することを確認してから修正し、全23件を再実行した。

1. 検知の一時的なunknown後に、回し続けているホイールが再度Space移動を起こす問題。入力を通す間も横入力時刻を保持し、250 msの無入力なしに再開しない。
2. AXのルートに設定したタイムアウトが子要素へ継承されない問題。各要素を読む前に設定し、設定失敗もunknownにする。第1段階のプローブにも同じ所有者の修正を適用した。

## 起動・画面確認

初期Preferencesがない状態で試用バンドルの起動とプロセスの存在を確認。初期値は一時停止で、実行へ切り替えていない。画面確認ツールはアプリ選択時に2回タイムアウトしたため、メニュー表示・設定画面のレイアウト・クリック操作・VoiceOverは確認済みとしない。

新しい権限を付与せず、BTTを終了・削除せず、Mos・LinearMouse・Karabinerの設定を操作していない。公開・push・ライセンス決定・ログイン項目登録も実施していない。

## 初版の入力範囲についての実装判断

公開CGEventだけで物理マウスを認証することはできない。初版はフェーズなしのホイール型入力を対象とし、連続値も受け付ける。フェーズ付きジェスチャーと慣性は通す。滑らか化アプリが慣性情報を消した場合に完全に区別できるとは主張しない。この制限が実マウス環境で支障になる場合は、受け入れ後へ先送りせず入力元の扱いを再検討する。
